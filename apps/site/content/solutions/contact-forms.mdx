<Section title="The problem" lede="A contact form is a few inputs on a page, and it still needs a server, a spam filter and somewhere for the messages to go.">

Static sites have nowhere to post a form. Adding a function for it means parsing the post, validating fields, keeping bots out, emailing the right person and getting the lead into your CRM or mailing list, and every public form attracts spam the day it goes up.

coss.com does this on one key: [Forms](/products/forms) gives each form an endpoint, [Risk](/products/risk) screens every submission, [email](/products/email) tells your team, and [contacts](/products/marketing-email) keep the leads you can write to later.

</Section>

<Section title="How it works" lede="Create a form, point your HTML at its endpoint, and accepted submissions come to you.">

```ts twoslash
import { Coss } from "coss";
const coss = new Coss();
declare const leadsAudienceId: string;
// ---cut---
const { data: form } = await coss.forms.create({
  name: "Contact us",
  allowed_origins: ["https://www.example.com"],
  fields: [
    { name: "email", type: "email", required: true },
    { name: "first_name", type: "text" },
    { name: "company", type: "text", max_length: 100 },
    { name: "message", type: "textarea", max_length: 5000 },
  ],
  // Your team gets an email, from your domain, and replies go to the submitter.
  notifications: { recipients: ["sales@example.com"], from: "forms@example.com" },
  // The submitter becomes a contact in your leads audience.
  contacts: {
    enabled: true,
    audience_ids: [leadsAudienceId],
    first_name_field: "first_name",
    properties: { company: "company" },
  },
});
// form?.endpoint: https://…/f/form_01k…
```

```html
<form action="https://…/f/form_01k…" method="post">
  <input type="email" name="email" required>
  <input type="text" name="first_name">
  <input type="text" name="company">
  <textarea name="message"></textarea>
  <input type="hidden" name="_next" value="https://www.example.com/thanks">
  <!-- The honeypot: people leave it empty, bots fill it in. -->
  <input type="text" name="_gotcha" style="display:none" tabindex="-1" autocomplete="off">
  <button>Send</button>
</form>
```

That's a working form with no JavaScript. To submit without a page load and show errors per field, add `attachForm`, which also sends a device token so Risk recognizes the browser:

```ts twoslash
import { attachForm } from "coss/forms";
// ---cut---
const form = document.querySelector<HTMLFormElement>("#contact");
if (form) {
  attachForm(form, {
    onResult(result) {
      if (result.ok) console.log("Thanks!");
      else if (result.errors) for (const error of result.errors) console.log(error.field, error.message);
    },
  });
}
```

To send leads to your CRM, handle the webhook:

```ts twoslash
import { verifyWebhook } from "coss";
declare const secret: string;
declare const request: Request;
declare function createLead(email: string | null, fields: Record<string, string | string[]>): Promise<void>;
// ---cut---
const event = await verifyWebhook(await request.text(), request.headers, secret);
if (event.type === "form.submission.received") {
  // Submitted values are untrusted input.
  await createLead(event.data.submitter_email, event.data.data);
}
```

<Section title="What you get" lede="Collect, screen and deliver submissions, from plain HTML, a script or a page coss.com hosts.">

<Features>

<Feature title="Any HTML form">
The endpoint takes the URL-encoded and multipart posts browsers send, and JSON. Define `fields` to validate types and required values, or leave them out and take any field. See [HTML forms](/docs/forms/html-forms).
</Feature>

<Feature title="Spam stays out">
A honeypot, then a Risk assessment with your own [rules](/docs/risk/rules) and [lists](/docs/risk/lists-and-feedback), a content check, and an optional Turnstile or hCaptcha. Spam is answered like a success, so bots learn nothing. See [spam filtering](/docs/forms/spam-filtering).
</Feature>

<Feature title="False positives come back">
What Risk wants reviewed waits as `held`. Release it or anything marked `spam`, and it's delivered as if it had been accepted, and Risk learns from it. If Risk can't be reached, submissions are delivered rather than lost.
</Feature>

<Feature title="Notifications your team can answer">
Up to 5 recipients get an email per accepted submission, with every field and a link to it in the dashboard, and a reply goes to the submitter. They come from your verified domain, or from coss.com as "form name via coss.com".
</Feature>

<Feature title="Leads in your contacts">
Submitters become [contacts](/docs/email/contacts), with their audiences, topics and properties, ready for [broadcasts](/products/marketing-email). Double opt-in can make new contacts confirm first. See [double opt-in](/docs/forms/double-opt-in).
</Feature>

<Feature title="Webhooks for everything else">
`form.submission.received` and `form.submission.flagged` reach your [webhooks](/docs/webhooks), signed, with what was submitted. Each destination retries on its own if it fails.
</Feature>

<Feature title="Hosted pages">
Turn on `hosted` and the endpoint also serves the form as a page rendered from its fields, to link to or embed, with no JavaScript needed. See [hosted pages](/docs/forms/hosted-pages).
</Feature>

<Feature title="Confirmed addresses and attachments">
`submitter.verify` holds a submission until the submitter clicks the link emailed to them. [File uploads](/docs/forms/file-uploads) take attachments, served only as downloads. They aren't scanned for malware, so treat them as untrusted.
</Feature>

</Features>
